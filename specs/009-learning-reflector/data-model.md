# Data Model: Learning Reflector

## Overview

The feature introduces no new persistent entity or database schema. It orchestrates transient extraction results into the existing semantic-memory record model.

## Learning Candidate

A transient result produced from exactly one latest user message.

| Field | Type | Validation and behavior |
|---|---|---|
| `hasLearning` | boolean | Required structured decision. False means no write is attempted. |
| `fact` | string | Required by the extraction schema; trimmed. When `hasLearning` is true, must be non-empty, concise, derived from an explicit durable statement, and pass secret checks. When false, ignored and never persisted. |

The candidate is not persisted. It must not include assistant-generated statements, one-off requests, or recognized credential values.

## Existing Memory

The existing `MemoryRecord` remains the only persistent entity.

| Field | Type | Validation and behavior |
|---|---|---|
| `id` | string | Existing unique identifier; generated by `MemoryStore`. |
| `userId` | string | Required owner. For learning, sourced from the validated chat request. For forgetting, sourced from trusted invocation context, never from model arguments. |
| `fact` | string | Non-empty validated fact produced by extraction; persisted by existing `MemoryStore.remember`. |
| `embedding` | number array | Generated and validated by existing embedding provider; persisted by existing SQLite adapter. |
| `createdAt` | date | Generated by existing memory service. |

Existing deduplication, recall, and per-user deletion behavior remains authoritative.

## Forget Preference Outcome

Transient result returned to the agent tool:

| Status | Meaning | Side effect |
|---|---|---|
| `deleted` | One sufficiently strong, unambiguous candidate was removed. | Exactly one user-owned record is deleted. |
| `not_found` | No candidate met the forget confidence threshold. | No deletion. |
| `ambiguous` | Multiple plausible candidates exist or the best candidate lacks a sufficient lead. | No deletion; tool result gives only same-user candidate facts needed for clarification. |

Persistence and embedding errors are tool failures, not success-shaped outcomes. A tool input or runtime context that fails Zod validation is rejected before lookup.

## Relationships and Lifecycle

- A user may own many existing memories; each memory belongs to exactly one user.
- One successful chat response schedules at most one learning candidate.
- A candidate creates zero or one memory: zero if the decision is negative, invalid, secret-like, or blank; one `remember` call otherwise. Existing deduplication may return an existing record rather than insert a duplicate.
- One forget request can remove at most one memory. Ambiguous and missing outcomes do not mutate storage.
